title: Editing devices
description: Set a device's template, instance count and IDs, params, field overrides, interval and autostart.

Click a device in the **Devices** tab, such as `office ×5`, to open the device editor. **Add device** creates a device called `device` on the project's first template (or the built-in `co2` when the project has none of its own) and selects it.

![The device editor showing the office device of the showcase project](/screenshots/device-editor.png)

The heading names the device, for example **Device office**. A problem with one value shows in red under that value's box, which gets a red outline; other problems with the device appear in red under the heading. As with templates, every change goes into the project at once, and running instances take it at once too, unless it changes how they connect ([Editing while running](/docs/concepts/editing-while-running)).

## Start device, Duplicate device and Delete device

**Start device** starts the device's instances that are not running. It is disabled while the device cannot run; hover over it to see where the problems are:

- **Fix the problems marked in red first**: the device's own problems, shown in the editor.
- **Fix the problems in the Problems tab first**: the device itself is fine, but its template or the broker settings have problems.

**Duplicate device** copies the device, with its template, count, params and all its other settings, and selects the copy; **Duplicate** in the device's right-click menu does the same. See [Duplicate device](#duplicate-device).

**Delete device**, or the Delete key while the device is selected, removes the device from the project without asking; Ctrl+Z brings it back ([Undo and redo](/docs/gui/window#undo-and-redo)). Instances of it that are running keep running as orphans until you stop them ([Running devices](/docs/gui/running-devices#orphans)).

## Settings

| Label            | What it sets                                                                    |
| ---------------- | ------------------------------------------------------------------------------- |
| **ID**           | The device's ID. A rename applies when you press Enter or leave the box.        |
| **Template**     | The template the device uses: the built-in templates first, then the project's. |
| **Count**        | How many instances the device runs, from 1 to 10,000 in the editor.             |
| **Instance IDs** | The IDs of the instances (see below).                                           |
| **Autostart**    | Ticked (**start when the project opens**): the device starts when the project opens. Unticked: it waits for you to start it. |
| **Interval**     | Tick **override** to give the device its own interval instead of the template's. |

### Instance IDs

Without **custom**, the editor shows the IDs Senzor generates from the device ID: `office` for a device with one instance, `office-0 … office-4` for five.

Tick **custom** to write your own pattern. The box starts with the pattern Senzor was already using, `{{ id }}` for one instance or `{{ id }}-{{ index }}` for more, so the IDs do not change until you edit it. While the pattern is one of these defaults, it follows the **Count**: going from one instance to three switches it to `{{ id }}-{{ index }}`. Once you edit the pattern, it stays as you wrote it. [Templates, devices and instances](/docs/concepts/templates-devices-instances) explains the patterns.

Changing the ID, **Count** or **Instance IDs** while instances run can drop the IDs of running instances. Those keep running as orphans until you stop them ([Running devices](/docs/gui/running-devices#orphans)).

### Interval override

When you tick **override**, the box starts at the template's interval (or 10s when the device's template is unknown), so nothing changes until you edit it. Untick it to go back to the template's interval. The box takes durations like `10s`, `500ms` or `1h`, as in the template editor.

## Params

Params are values a device passes to its template, such as `room = "office"` in the showcase project, used in the template as `{{ room }}`.

Each param is a row with a name box, a type selector, a value box and **Remove**. **Add param** adds an empty text param called `param`. A new name applies when you press Enter or leave the box, so the rows do not reorder while you type.

Values are typed. The selector offers **text**, **number** and **bool**, and typing never changes the type:

- A text value keeps exactly what you type, spaces included, so `007` stays the text `"007"`.
- A number value only accepts a number; anything else stays in the box with the hint **use a number, e.g. 42 or 22.5** and the param keeps its previous value.
- A bool value only accepts `true` or `false`.

To change the type, pick it in the selector. Types that the text in the box does not fit are disabled; hover over one to see why. Switching keeps the text you typed: `42x` in a number box becomes the text `"42x"` when you switch to **text**.

## Field overrides

An override changes one setting of a template's field for this device only, such as where a random walk starts. **Field overrides** has a block for each field of the device's template. Its header names the field by its key, then the name and unit the template gives it, and says what the device overrides: **co2 — CO2, ppm** followed by **start overridden**, or **not overridden**. A block starts closed when the device overrides nothing in it; click the header to open it.

Inside, each setting of the field has a row with a checkbox, its name and a box: **generator**, the generator's parameters, **noise**, **unit** and **name**. As the editor notes: **Tick a setting to change it for this device; the others show the template's value.**

- An unticked setting shows the template's value, greyed out.
- Ticking a setting copies the value the field uses into the override, so nothing changes until you edit it. A field without noise shows **none**; ticking **noise** starts it at 0.1. Ticking **name** on a field without a name starts it at the field's key, and ticking **unit** on a field without a unit leaves it empty, which is a problem until you type one.
- Unticking a setting removes it from the override. When nothing in a block is ticked, the device has no override for that field.

For example, the showcase's `meeting` device starts its CO2 higher than the other rooms:

```toml
fields.co2 = { start = 1100 }
```

In the editor, that is **start** ticked at 1100 in the **co2** block. The boxes work as in the [template editor](/docs/gui/editing-templates#fields): **period** and **phase** take durations, **values** a comma-separated list, and a `constant`'s **value** has a type selector. Text a box cannot read stays in it with a hint, such as **use e.g. 10s, 500ms, 1h**, and the device keeps the previous value.

### Another generator

Tick **generator** to give the device another kind of generator for the field, then pick it. Picking a generator sets that generator's default parameters, the same ones the template editor starts from, so the field stays valid; for `sine`, center 0, amplitude 1, period 1m and phase 0s. Its required parameters stay ticked while **generator** is: hover over one of their checkboxes to see **Needed while the generator is overridden**. The field keeps the template's unit and name unless you tick those too.

Untick **generator** to go back to the template's generator. The parameters it does not have are dropped from the override, and so are the ones set to the template's own value.

### Problems with overrides

A problem with an override, such as `` field `co2` override: start must be between min and max ``, shows in red under the block's header, which gets a red outline.

A project file can hold overrides the boxes cannot show. A value of the wrong type, such as `start = "high"`, shows **cannot read "high"** next to the box and stays in the file until you edit the setting. A key that is not a setting of the field's generator, such as a misspelled `strat`, shows as **strat is not a setting of random_walk** with a **Remove** button.

If you switch the device to a template that lacks an overridden field, the override shows in red as, for example, **co2 (not in the template)**, with a **Remove override** button.

[Templates, devices and instances](/docs/concepts/templates-devices-instances) explains how overrides combine with the template's fields, and the [project file reference](/docs/reference/project-file) lists the keys.

## Duplicate device

The copy goes right after the original, under the ID `<id>-copy`, or `<id>-copy-2`, `<id>-copy-3` and so on when that is taken. For `office`, that is `office-copy`. It does not start by itself, even with **Autostart** on: start it like any other device.

Instance IDs must be unique, so the copy keeps a custom **Instance IDs** pattern only when that pattern gives it new instance IDs, for example one that uses `{{ id }}`. A pattern such as `room-{{ index }}` would give the copy the original's instance IDs, so the copy uses the default pattern instead (`office-copy-0`, `office-copy-1`, …).
