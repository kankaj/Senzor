Start the GUI with a project file, or without one to begin with an empty project:

```bash
# Open a project
senzor examples/showcase.toml

# Or start with an empty project
senzor

# Open a project with MCP already on, so AI agents can connect
senzor --mcp examples/showcase.toml
```

`--mcp` turns on the **MCP** switch in the [settings](/docs/gui/settings) at launch, and
`--mcp-port <PORT>` picks another port than the one in the settings, 18830 unless you changed it (and turns MCP on too). Neither changes what the settings remember. See
[When an agent is connected](#when-an-agent-is-connected).

![The Senzor window with the showcase project running and instance office-0 selected](/screenshots/window.png)

The window has five parts: the top bar, the left panel with your devices and templates, the detail panel in the middle, the bottom panel with the message log and the problems, and the status bar along the bottom edge. You can resize the left and bottom panels by dragging their edges.

## Top bar

Each button shows an icon before its name; in a narrow window, the buttons continue on a second row. From left to right:

- **The project's name.** This is the file name, or **untitled** for a project you have not saved yet. A `*` after the name means there are unsaved changes. The window title shows the same, for example `Senzor — showcase.toml*`.
- **Broker: localhost:1883** shows the broker's host and port. Click it to open **Project settings**: the [broker settings](/docs/gui/broker-settings), where you also choose MQTT 5 or 3.1.1, and the [seed](/docs/concepts/reproducible-runs).
- **New**, **Open**, **Save** and **Save as** work on the project file, the clock next to **Open** lists the [recent projects](/docs/gui/files#recent-projects), and the books next to the clock list the [examples](/docs/gui/files#examples). While there are unsaved changes, **Save** is filled with the accent colour; hover over it to read **Save the unsaved changes**. See [Files](/docs/gui/files).
- **Undo** and **Redo**, the two curved arrows after **Save as**, take back an edit to the project and apply it again. See [Undo and redo](#undo-and-redo).
- **Start all** and **Stop all** start and stop every device. See [Running devices](/docs/gui/running-devices).
- **starting devices…** can appear for a moment after you open another project or start a new one. Hover over it to read **Waiting for the previous project's devices to go offline**: the new project's devices start once the old ones are offline (see [Autostart](/docs/gui/running-devices#autostart)).
- **The gear**, at the right end, opens the [settings](/docs/gui/settings): the theme, the zoom, and the **MCP** switch that lets AI agents control the window. Hover over it to read **Settings**.
- **A robot** in the accent colour appears next to the gear while MCP is on, so you can see that AI agents can control the window. Hover over it for the address they connect to, and click it to open the settings, where you turn MCP off.

## Keyboard shortcuts

| Keys | Does |
| ---- | ---- |
| Ctrl+N | **New** |
| Ctrl+O | **Open** |
| Ctrl+S | **Save** |
| Ctrl+Shift+S | **Save as** |
| Ctrl+Z | **Undo** |
| Ctrl+Shift+Z or Ctrl+Y | **Redo** |
| F5 | **Start all** |
| Shift+F5 | **Stop all** |
| Ctrl+Comma | Open the [settings](/docs/gui/settings) |
| Ctrl+F | Show the message log and put the cursor in its **Filter** |
| Delete | Delete the selected device or template; Ctrl+Z brings it back |
| Ctrl++ or Ctrl+= | Zoom in |
| Ctrl+- | Zoom out |
| Ctrl+0 | Reset the zoom to 100 % |
| Ctrl+Q | Close the window, asking about unsaved changes first |

On macOS, use Cmd instead of Ctrl. Hover over a button in the top bar to see its shortcut. While a dialog is open, such as **Unsaved changes**, the shortcuts do nothing until you answer it.

## Undo and redo

**Undo** takes back the latest edit to the project, and **Redo** applies it again. Each edit is one step: adding or removing a device or template, a rename, or a change in a form. What you type into one field counts as one step until you leave the field. Senzor keeps the last 100 steps; a new edit after an undo drops what you could have redone. Undoing back to the saved file removes the `*` from the title.

While you are typing into a field, Ctrl+Z and Ctrl+Y belong to the field and take back what you typed there; the project follows. Leave the field to undo whole edits again. Delete also belongs to the field while you type: it deletes text, not the selected device.

Edits an AI agent makes over [MCP](/docs/mcp) are steps too, so Ctrl+Z also takes back the agent's latest edit. Opening a project or starting a new one starts a fresh history; saving keeps it.

## Left panel

The left panel has two tabs.

**Devices** lists every device in the project, with its instances under it. A device with problems lists only its instances that still run, as orphans. A device shows its ID and instance count, such as `office ×5`. Each instance has a coloured dot for its status:

| Dot   | Status                     |
| ----- | -------------------------- |
| Green | Online                     |
| Amber | Connecting or Reconnecting |
| Grey  | Stopped                    |
| Red   | Failed                     |

Click a device or an instance to show it in the detail panel. Right-click it for a menu that starts, stops, restarts and kills it ([Running devices](/docs/gui/running-devices)). **Add device** adds a new device and selects it. The box with the magnifying glass above it finds devices and instances, and the menu next to it shows only the instances in one state; see [The device tree](/docs/gui/running-devices#the-device-tree).

**Templates** lists the templates. **Built-in** lists the templates that ship with Senzor (`co2`, `temperature`, `humidity`). **Project** lists the project's own templates; right-click one and choose **Duplicate** to copy it. **Add template** adds a new template to the project and selects it.

## Detail panel

The middle of the window shows what you selected on the left:

- An instance: its status, counters and live values, where you can also pin values. See [Instance view](/docs/gui/instance-view).
- A device: the device editor. See [Editing devices](/docs/gui/editing-devices).
- A project template: the template editor with a live preview. See [Editing templates](/docs/gui/editing-templates).
- A built-in template: a read-only view with **Copy into project…**.

With nothing selected it says **Select a device, an instance or a template on the left.**

A new project that is still blank shows the welcome screen instead. That is how the window starts without a file, and what **New** gives. **Welcome to Senzor** offers **Add your first device**, **Open a project** and **Set the broker**, the [examples](/docs/gui/files#examples), your [recent projects](/docs/gui/files#recent-projects), and links to the **Quick start guide** and this documentation. The welcome screen goes away once the project has a device or a template, a file, or unsaved changes.

## Bottom panel

The bottom panel has two tabs: **Message log** and **Problems**.

### Message log

![The message log listing the messages the showcase devices published](/screenshots/message-log.png)

The message log lists the messages your instances publish, newest at the bottom. Each row shows:

- The time in UTC with milliseconds, for example `14:02:11.123Z`.
- The instance ID.
- The topic.
- The payload. Line breaks and runs of spaces become one space, and a payload longer than 200 characters is cut off with `…`.

The log keeps the last 1,000 messages of all instances together. It shows the messages your templates define, not the `online` and `offline` availability messages. While you are scrolled to the bottom, the list follows new messages.

- **Filter** shows only the rows whose topic contains the text you type. The match is case-sensitive. Ctrl+F shows the message log and puts the cursor in the box.
- **Pause** freezes the list so you can read it while the devices keep publishing. **Resume** shows the live log again.

### Problems

![The Problems tab listing a validation error](/screenshots/problems.png)

Senzor validates the project after every edit. While the project is valid, the tab reads **Problems** and shows **No problems.** When something is wrong, the tab's label turns red and counts the problems, for example **Problems (2)**.

Each problem names what it is about, then what is wrong, for example:

```text
device `bad`: unknown template `nope`
```

Click a problem to go to it: a device or template problem selects that device or template (switching the left tab if needed), and a broker problem opens the broker settings. When the problem is about one value, such as a device's **Instance IDs**, the cursor goes into that box.

In the editors, a problem with one value shows under that value's box, which gets a red outline. Problems that no single box holds, such as a template whose topic the device's params break, show in red under the editor's heading.

A device with problems cannot start, and neither can the devices of a template with problems. A broker problem stops every device from starting. Instances that were already running keep running with their last valid settings; see [Editing while running](/docs/concepts/editing-while-running). The [validation errors reference](/docs/reference/validation-errors) explains each message.

## Status bar

The status bar along the bottom edge of the window shows, from the left:

- The broker's host and port, then **connected** in green once an instance is online, **cannot connect** in red while instances are reconnecting or failed and none is online, **connecting…** while they connect, or **not connected** while nothing runs. Click it to open the [broker settings](/docs/gui/broker-settings).
- How many instances are online, connecting, reconnecting and failed, for example **11 online**. A state with no instances is left out; with nothing running, it reads **nothing running**.
- How many messages per second the instances publish, counted over the last 5 seconds, for example **4.6 msg/s**.
- At the right end, **MCP off**, or **MCP on :18830** with the port while AI agents can control the window. Click it to open the [settings](/docs/gui/settings).

## When an agent is connected

Turn on the **MCP** switch in the [settings](/docs/gui/settings) to let an agent connect. While MCP is on, a robot shows next to the gear at the right end of the top bar.

While MCP is on, an agent such as Claude Code works on the same project as you. Its changes appear in the window right away, and its edits mark the project as unsaved like yours do. Text you are still typing into a field is dropped when the agent edits the project. While a dialog is open, the agent cannot save, open or start a new project. See [Working together in the GUI](/docs/mcp#working-together-in-the-gui).
