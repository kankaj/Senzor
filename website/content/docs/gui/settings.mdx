title: Settings
description: The app's own settings, its language, theme, zoom, notifications, the MCP endpoint and update checks, and where Senzor keeps them.

The settings belong to the app, not to a project: they are the same whichever project you open, and they are never written to a project file. To open them, click the gear at the right end of the top bar; hovering over it reads **Settings**. The **Settings** window opens in the middle of the window. Close it with the **×** in its title bar.

![The Settings window with MCP on, showing the address agents connect to](/screenshots/settings.png)

## Language

**Language** chooses the language of the window: **English**, the default, or **Čeština** (Czech). Each is named in its own language, so you can find your way back from either. The window switches as soon as you click, and Senzor starts in the same language the next time.

The language covers everything the window shows: menus, forms, the `?` help texts, the Problems tab and the problems next to a box, notifications and What's new. A few texts stay English: TOML keys and values, generator and encoding names, and the error texts other components report, such as a TOML parse error or a broker's reason for refusing a connection, which appear inside a translated sentence. This documentation, `senzor-cli` and MCP are in English only.

## Theme

**Theme** chooses the colours of the window:

- **System** follows your operating system's light or dark setting. This is the default.
- **Light** and **Dark** use those colours whatever the system uses.

The window changes as soon as you click, and Senzor uses the same theme the next time it starts.

## Zoom

**Zoom** makes everything in the window larger or smaller, in steps of 10 %, from 20 % to 500 %. Click the minus to zoom out and the plus to zoom in; the percentage between them shows the zoom. **Reset** goes back to 100 %. The keyboard does the same anywhere in the window: Ctrl++ or Ctrl+= zooms in, Ctrl+- zooms out and Ctrl+0 resets; on macOS, use Cmd instead of Ctrl. Hover over a button to see its shortcut.

Senzor starts with the zoom you used last.

## Notifications

The **Notifications** switch, **when an instance fails in the background**, shows a desktop notification when an instance fails while the window does not have the focus or is minimized; see [Status](/docs/gui/instance-view#status). It is on unless you turn it off, and Senzor remembers your choice.

## MCP

The **MCP** switch, **let AI agents control this window**, turns on the endpoint AI agents such as Claude Code connect to. While it is on, the **Address** row shows where agents connect, `127.0.0.1:18830`, a robot shows next to the gear in the top bar, and the status bar reads **MCP on :18830**; clicking the robot opens the settings. Hover over the switch for the full URL. Turn the switch off to stop the endpoint, which disconnects connected agents.

If the port is taken, a dialog says why, unless another dialog is already open, and the switch stays off. The reason also shows in red under the switch, after **Could not start:**. Click the switch to try again.

**MCP port** is the port MCP listens on, 18830 unless you change it. Change it while MCP is off; while it is on, the box is disabled with the hint **Turn MCP off to change its port**.

The switch **let agents on other machines connect, with a token** makes MCP listen on every address of this computer instead of `127.0.0.1`, and asks every agent for a token. Senzor makes the token the first time you turn the switch on and keeps it in its settings. Below the switch, **Copy token** puts it on the clipboard; agents send it as the HTTP header `Authorization: Bearer <token>`. **New token** replaces it, and agents that use the old one can no longer connect. While MCP is on, the **Address** row then reads **this machine's name or address, port 18830**: agents use `http://<this computer's name or IP address>:18830/mcp`. Turning the switch on or off, or a new token, restarts MCP, which disconnects connected agents.

Senzor remembers the port and whether you left MCP on: a window you close with MCP on starts the next time with MCP on. `--mcp` and `--mcp-port` turn MCP on for one launch without changing what Senzor remembers. See [Set up Claude Code with the GUI](/docs/mcp#set-up-claude-code-with-the-gui).

## Updates

The **Updates** switch, **say when a newer version is out**, lets Senzor ask GitHub whether a newer release exists. When one does, the [status bar](/docs/gui/window#status-bar) reads **Senzor 1.1.0 is out**, with the new version, and the **Version** row adds **1.1.0 is out**. Click either to open the release's page on GitHub, which lists what is new and has the downloads. Pre-releases do not count.

Senzor asks when it starts, at most once a day, in the background, so the window never waits for the answer. It sends one HTTPS request to GitHub's API at `api.github.com` for the latest release of the [Senzor repository](https://github.com/kankaj/Senzor). The request names only the program and its version, such as `Senzor/1.0.0`; nothing about you or your projects is sent, and GitHub sees your IP address as any website does. Hover over the switch for a summary. Without a network connection, or when GitHub does not answer within 5 seconds, nothing is shown and Senzor asks again the next time it starts.

The switch is on unless you turn it off, and Senzor remembers your choice. While it is off, Senzor asks nothing and hides a newer version it found before. `senzor-cli` never checks for updates.

Senzor from the Microsoft Store is updated by the Store. There the row reads **the Microsoft Store keeps Senzor up to date**, without the switch, and Senzor never asks GitHub.

## Version and credits

**Version** shows the version of Senzor you are running, followed by **1.1.0 is out** when a newer version is out (see [Updates](#updates)), **Licence** its licence, the [Apache License 2.0](/docs#licence), and **Author** who wrote it. Under them, **What's new** lists what this version brings, **Documentation** opens this site at the docs of the version you are running, as the `?` next to each setting does, and **Source code** the [Senzor repository on GitHub](https://github.com/kankaj/Senzor). **Open-source credits** unfolds a list of the projects built into Senzor, each with its licence and a link to its page: among them egui and eframe for the window, Phosphor Icons for the icons, the Ubuntu and Hack fonts, and rumqttc for MQTT.

## What's new after an update

The first time Senzor opens after an update, it shows **What's new in Senzor** with the highlights of every version since the one you ran before. **Full changelog** opens the complete list of changes, [`CHANGELOG.md`](https://github.com/kankaj/Senzor/blob/main/CHANGELOG.md); **OK** closes it. A first installation shows nothing: the welcome screen covers that. Senzor knows the version that ran before from the file below.

## Where Senzor keeps them

Senzor saves its settings in one file, `app.ron`, when you close the window and every 30 seconds while it runs. The same file holds the [recent projects](/docs/gui/files#recent-projects), whether notifications are on, the MCP port and whether MCP was on, whether update checks are on with when Senzor last asked and the newest version it found, the selected tabs of the left and bottom panels, the panels' sizes, the version of Senzor that last ran, the size of the window and, where the desktop allows it, its position:

| System  | File                                                    |
| ------- | ------------------------------------------------------- |
| Linux   | `~/.local/share/cz.kankaj.senzor/app.ron`               |
| macOS   | `~/Library/Application Support/cz.kankaj.Senzor/app.ron` |
| Windows | `%APPDATA%\cz.kankaj.Senzor\data\app.ron`               |

On Linux, if `XDG_DATA_HOME` is set to an absolute path, the folder is `$XDG_DATA_HOME/cz.kankaj.senzor` instead. Senzor from the Microsoft Store runs in a package, and Windows keeps the files it creates in `%APPDATA%` in the package's own folder: its settings are in `%LOCALAPPDATA%\Packages\43614JaroslavKaka.Senzor_qrj5pzk60eqe4\LocalCache\Roaming\cz.kankaj.Senzor\data\app.ron`, unless another Senzor on the same computer made `app.ron` first, which they then share. To go back to the defaults, close Senzor and delete the file.
