title: Installation
description: How to get Senzor 1.0.0.
---

Senzor comes as two programs, each a package of its own: **`senzor`**, the window, and
**`senzor-cli`**, the headless runner for terminals, Docker and CI. Install either or both; they
read the same project files. Builds exist for Linux, macOS and Windows, each on x86_64 and ARM.

## With a package manager

A package manager installs the right build for your computer and updates it with everything else.

### macOS: Homebrew

```bash
brew install --cask kankaj/tap/senzor   # the window, Senzor.app
brew install kankaj/tap/senzor-cli      # the headless runner
```

Both come from Senzor's own tap, [kankaj/homebrew-tap](https://github.com/kankaj/homebrew-tap),
which Homebrew adds by itself the first time. The window needs macOS 10.13 or later on Intel Macs
and macOS 11 or later on Apple Silicon. Senzor is not signed by Apple, so macOS blocks it the
first time; see [First start on macOS](#first-start-on-macos).

### Windows: Microsoft Store

The window is available in the Microsoft Store:

<a href="https://get.microsoft.com/installer/download/9pc0635wjf44?referrer=appbadge" target="_self" >
    <img src="https://get.microsoft.com/images/en-us%20dark.svg" width="200"/>
</a>

The Store keeps that copy up to date, so it does not ask GitHub for new versions (see
[Updates](/docs/gui/settings#updates)). Install the window from one place only: the Store's copy
and the one from the MSI are separate installations. For the headless runner, or to install
the window without the Store, see [From the downloads](#from-the-downloads).

### Docker: senzor-cli

`senzor-cli` is also a container image, `ghcr.io/kankaj/senzor-cli`, for Linux on x86_64 and ARM.
Mount the folder with your project at `/work` and give the command after the image name:

```bash
docker run --rm -v "$PWD:/work" ghcr.io/kankaj/senzor-cli:1 run project.toml
```

Each release is tagged with its version (`1.2.3`), its minor version (`1.2`), its major version
(`1`) and `latest`; `:1` follows every 1.x release. The image runs `senzor-cli` as a user other
than root and carries the binary of the release's Linux download. [CI and Docker](/docs/recipes/ci-and-docker)
shows it next to a broker, with Docker Compose and in GitHub Actions.

Inside the container, `localhost` is the container itself, so a broker on your machine is not at
`localhost`. On Linux, add `--network host`; with Docker Desktop, use `host = "host.docker.internal"`
in the project.

### Rust: crates.io

Both programs are on [crates.io](https://crates.io/crates/senzor), and Cargo builds them on your
computer:

```bash
cargo install senzor-cli   # the headless runner
cargo install senzor       # the window
```

You need [Rust](https://www.rust-lang.org/tools/install) 1.99 or later and a C compiler (`gcc` or
`clang`; on Windows, the Visual Studio Build Tools that the Rust installer offers). Cargo puts the
programs into `~/.cargo/bin`, which the Rust installer adds to your `PATH`. On Linux the window
needs the same libraries as the [downloads](#from-the-downloads) to run; building needs no other
packages.

### Linux

We are working on publishing Flatpak packages, and adding Arch Linux
packages in the AUR (`senzor-bin` and `senzor-cli-bin`) as soon as the AUR accepts new maintainers
again. Until then, use the [downloads below](#from-the-downloads), or for `senzor-cli` the
[Docker image](#docker-senzor-cli).

`senzor-<target>.tar.xz` for macOS and `senzor-<target>.zip` for Windows.

### Linux

Unpack the archive and put the program on your `PATH`, for example in `~/.local/bin`:

```bash
tar -xJf senzor-x86_64-unknown-linux-gnu.tar.xz
install -Dm755 senzor-x86_64-unknown-linux-gnu/senzor ~/.local/bin/senzor
```

The builds need glibc 2.35 or later (Ubuntu 22.04, Debian 12, Fedora 36 and newer). The headless
runner needs nothing else. The window needs a desktop with Wayland or X11, the keyboard library
xkbcommon and a graphics driver, which a desktop installation has. On a minimal system:

```bash
# Debian and Ubuntu
sudo apt install libxkbcommon0 libxkbcommon-x11-0 libwayland-client0 libx11-6 libxcursor1 libxi6 libxrandr2 libvulkan1 mesa-vulkan-drivers
# Fedora
sudo dnf install libxkbcommon libxkbcommon-x11 libwayland-client libX11 libXcursor libXi libXrandr vulkan-loader mesa-vulkan-drivers
```

To have Senzor in your desktop's application menu, with its icon, copy the desktop entry and the
icons from the archive's `linux` folder; its `README.txt` has the commands.

### macOS

Unzip `Senzor-<target>.zip` and drag **Senzor.app** to **Applications**, then see
[First start on macOS](#first-start-on-macos). For the headless runner, unpack the archive and
put `senzor-cli` on your `PATH`, for example in `/usr/local/bin`.

### Windows

Run the MSI. It installs Senzor for all users, adds it to the Start menu and replaces an older
version; Windows lists it under **Installed apps**. Windows may warn about it the first time; see
[First start on Windows](#first-start-on-windows). For the headless runner, unzip the archive and
put `senzor-cli.exe` in a folder on your `PATH`.

## First start on macOS

Senzor is not signed or notarized by Apple, so macOS refuses to open it the first time. Open it
once from **Applications**, then choose **System Settings** > **Privacy & Security** >
**Open Anyway**. On macOS 14 and earlier you can right-click **Senzor.app** and choose **Open**
instead. macOS remembers the choice. A `senzor-cli` from a downloaded archive is blocked the same
way; remove the download mark once:

```bash
xattr -d com.apple.quarantine /usr/local/bin/senzor-cli
```

## First start on Windows

The MSI is not signed yet, so Windows SmartScreen may show **Windows protected your PC** when you
run it. Choose **More info**, then **Run anyway**. The Microsoft Store's copy opens without it.

## Updates

The window tells you when a newer version is out (see [Updates](/docs/gui/settings#updates)); the
Microsoft Store updates its copy by itself. To update:

```bash
brew upgrade --cask senzor && brew upgrade senzor-cli   # Homebrew
docker pull ghcr.io/kankaj/senzor-cli:1                 # Docker
cargo install senzor senzor-cli                         # crates.io: builds the newer version
```

From the downloads, install the new release over the old one: the MSI replaces the installed
version, and on Linux and macOS you replace the files.

## Checking a download

Every file has its SHA-256 checksum next to it, as `<file>.sha256`, and the release lists them all
in `sha256.sum`. Download the checksum with the file and check it:

```bash
sha256sum -c senzor-x86_64-unknown-linux-gnu.tar.xz.sha256   # Linux
shasum -a 256 -c Senzor-aarch64-apple-darwin.zip.sha256      # macOS
```

GitHub also keeps a signed record of which workflow built each file. With the
[GitHub CLI](https://cli.github.com/):

```bash
gh attestation verify senzor-x86_64-unknown-linux-gnu.tar.xz --repo kankaj/Senzor
```

## Uninstalling

Remove Senzor the way you installed it: `brew uninstall --cask senzor` (with `--zap` it also
removes the settings), the Store's copy and the MSI under
**Settings** > **Apps** > **Installed apps**, and downloaded files by deleting them. The window's
settings stay in one file until you delete it; see
[Where Senzor keeps them](/docs/gui/settings#where-senzor-keeps-them).

## Building from source

To build a released version, use [crates.io](#rust-cratesio). To build the code in the
repository, you need [Rust](https://www.rust-lang.org/tools/install) installed with rustup: the repository
names the Rust version it is built with in `rust-toolchain.toml`, and rustup installs that version
the first time you build. In a clone of the [Senzor repository](https://github.com/kankaj/Senzor),
run:

```bash
cargo install --path crates/senzor       # the window, `senzor`
cargo install --path crates/senzor-cli   # the headless runner, `senzor-cli`
```

Cargo puts both programs into `~/.cargo/bin`, which the Rust installer adds to your `PATH`.
